## Phase 2: tap to destroy

Click or tap the leather bag to start the explosion. Background clicks, orbit drags exceeding six pixels, and multi-touch gestures do not trigger it. Additional clicks are locked out once it starts. Sound is synthesized locally after that gesture, with a small mute control. Replay appears after completion and remounts a clean physics world while reusing the same AudioContext.

The state machine is `IDLE → EXPLODING → FALLING → COMPLETE`. Pressure and bass begin immediately; the actual bag surface switches to 36 thick irregular leather shards at 0.15 seconds. Logo triangles travel with their corresponding leather shards. Rapier supplies convex collision shapes, area-based masses, impulses, spin, damping and gravity. Contacts between shards begin after initial separation to avoid overlapping convex hulls causing explosive numerical separation. Instanced bent textile scraps and fine dust originate inside the bag. A shader sphere provides the short shockwave; the chain jolt remains anchored at the upper suspension. All scene elements clear at 3.5 seconds, leaving black plus the small Replay control. Rendering switches to demand mode after completion.

Reduced-motion mode removes camera shake and shockwave, reduces fragment speed/spin and uses fewer textile particles. Mobile uses fewer particles than desktop. Audio is optional if the browser cannot create an AudioContext.

This is a procedural fracture approximation of the approved geometry, **not production-quality Blender-authored leather tearing or a cloth simulation**. Fragment boundaries follow an irregular surface partition; leather does not dynamically stretch or propagate cracks. Synthesized bass/noise layers approximate an impact and tear; they are not professionally recorded leather sounds.

For production assets, pass `fracturedModelUrl="/assets/bag-fractured.glb"` to `PunchingBagIntro`. The fractured GLB should contain one closed mesh per shard, with transforms matching the intact bag (height 3.14m, +Y up, +Z front), baked PBR textures, and the official logo baked into the relevant shard UVs. Keep both intact and fractured assets aligned. The loader preserves authored shard materials. If supplying an alternate intact `asset.modelUrl`, also supply its matching fracture asset; the default procedural fracture matches only the default approved bag. `onExplosionComplete` fires once per run; the main route uses it to reveal the battle-rope hero.

`node scripts/test-explosion.cjs` exercises background/drag rejection, click, duplicate rejection, timeline states, replay, touch, mute and reduced-motion completion against a running local app. It uses headless Edge on Windows; set `BROWSER_EXECUTABLE` to override. Screenshots and the result are written to ignored `qa/`. Browser audio initialization is exercised; listening quality still requires a human check.

Adjacent frames blend on a transparent additive canvas, so 24 FPS source steps can be presented between frame boundaries. Original frame assets and attribution are unchanged. A fixed GSAP pin survives metadata loading; scrub damping and lower mobile DPR reduce abrupt wheel/touch updates and canvas work. Development and production build directories are separated in `next.config.mjs` so an editor dev server cannot overwrite the phone preview.

Run `npm run pack:evolution` after extracting/rebuilding frames; it creates optional 4-frame binary transport batches with unchanged WebP payloads. Malformed batches fall back to individual WebP requests. The portable ZIP remains the original individual-frame archive, with optional batch metadata removed. `npm run assets:evolution` also rebuilds the batches.

`npm run check:evolution-smoothness` simulates 6 Mbps / 70ms latency with a cold browser cache and 10 seconds near the section (browsing the preceding trainers/membership content), followed by a five-second continuous scroll. The measured run recorded 150 blended pose changes and an 83ms longest integer-frame hold; this is a controlled browser result, not a claim about every phone. `EVOLUTION_WARMUP_MS=2200` tests a much more abrupt cold jump: on that path network loading can still be visible. The section begins warming 3600px before entry to cover normal browsing.

## Iron World hero

The hero now presents a procedural Three.js concept gym: a loaded power rack and bench, two-tier dumbbell rack, two treadmills, hanging punching bag and loose foreground weights. Ceiling portals, illuminated floor edges and a tiled platform create depth across the section. No remote models or textures are needed. The existing punching-bag entrance reveals this scene.

Desktop uses a wide architectural camera with subtle pointer parallax and a short scroll dolly. Mobile places the copy and trial button above a separately framed gym view; touch scrolling remains native. Reduced motion uses a still camera and bag, and rendering pauses outside the viewport. A local concept photograph remains available if WebGL fails. This is an illustrative space, not a representation of verified club inventory.

Run `npm run check:hero` against a local server on port 3000, or set `IRON_WORLD_TEST_URL`. It checks desktop, tablet, 390px and 320px layouts, trial dialog, Programs navigation, reduced motion, WebGL fallback and the homepage entrance. Screenshots and results are saved under ignored `qa/iron-world-*`. Run `npm run build` for production validation.
